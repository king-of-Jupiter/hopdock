# Direct import from Termius

Settings contains one compact Import from Termius button at the right of Host library. Clicking it automatically finds the local Termius profile, reads it through the built-in reader and imports the resulting records. No file picker, JSON export, external exporter command or user-installed Python is required.

The reader is based on the offline migration in [Termorator](https://github.com/king-of-Jupiter/termorator/tree/main/tools/termius-to-termorator) and the MIT-licensed [termius-export](https://github.com/y01and3/termius-export), pinned to d1a34e9bbf1dcf63dbcb910cfc24d54460a287d0. Chromium/V8 decoding dependencies are pinned in tools/termius-reader-requirements.txt. A PyInstaller executable is built per platform and bundled through electron-builder extraResources; Python is needed only to build it.

The reader locates Termius IndexedDB and copies its encrypted database into a temporary snapshot, excluding the exclusive LOCK file. It reads the local encryption key from the current user's OS credential store, authenticates it against encrypted data, decrypts and normalizes records in memory, and sends them to Electron main over a bounded stdout pipe. It does not change Termius files, open Termius, connect to servers or write a plaintext export. The snapshot is removed on completion.

Passwords/passphrases go into safeStorage; private keys go into managed Keychain files. Host and group IDs and key associations are retained through stable source-based IDs. Both host password and key are imported as combined authentication. Repeat imports reuse/skip existing records rather than overwriting local edits. Malformed normalized records fail before persistence; new secrets and key files are rolled back if final save fails.

Nested group and snippet package paths appear as full flat paths. Proxy configurations, forwarding rules and agent forwarding remain unsupported and are reported in import notes. Invalid-address hosts and unusable keys are skipped with notes. Hosts missing source credentials/username receive notes; no credentials are invented. The existing normalized migration contract is an internal transport, not a file the user is asked to supply.

Profile-not-found, missing/mismatched local encryption key, unsupported encryption, locked/unreadable data, timeout and missing packaged helper have designed errors. Close Termius and retry if its data cannot be read. The reader has a two-minute timeout and a 64 MiB output limit; raw reader diagnostics are not exposed.

Build helper: npm run build:termius-reader --workspace apps/desktop. The dist/dist:publish scripts and platform CI builds prepare it automatically. Dependency notices ship beside the executable. The copied Termorator normalizer has a small adaptation to preserve leading/trailing whitespace in passwords.

Validation on Windows: 28 isolated Electron scenarios, 19 browser checks, importer/error unit cases, typecheck and build passed. The direct-import scenario verifies that no file picker opens, credentials work with a local SSH fixture, snippets execute, duplicate imports skip records and malformed data leaves the library unchanged. An opt-in real-profile test (node tests/desktop/termius-direct-real.mjs) tested the actual bundled reader against this machine's Termius data, imported 36 hosts, 3 groups, 4 keys and 22 snippets into a temporary isolated Hopdock profile, then verified duplicate handling and deleted that test profile. The source contained 37 hosts; one invalid-address record was skipped. The user's normal Hopdock vault was not populated by testing. macOS/Linux helper builds are configured but were not executed locally.
